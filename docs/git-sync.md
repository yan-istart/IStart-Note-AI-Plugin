# 百度网盘 Git 同步

Git 模式用 JavaScript Git 内核保存真实提交，通过百度网盘上传、下载标准 Git bundle 文件。桌面、Android 和 iOS 使用相同协议，不需要系统 Git、终端或额外服务器。

## 使用

1. 在设置中启用百度网盘同步，填写百度应用信息并完成授权。
2. 选择「Git 版本同步」，在所有设备填写相同的远端路径。
3. 点击「打开同步 → 开始同步」，或侧边栏「手动同步」。
4. 若有冲突，选择本地或云端版本；文本冲突也可编辑合并内容后继续。
5. 在「版本历史」填写文件路径，选择提交并对照当前内容；可恢复单个文件，包括已经删除的文件。

自动 Git 同步和启动时拉取配置默认关闭。这些开关属于本设备偏好，不会被云端配置开启。可选自动 Git 同步在前台每分钟运行，开启后也在启动时运行；应用被暂停或关闭时不保证继续同步。默认只在用户点击时创建提交和交换版本包。

## 从原有文件同步迁移

已有配置继续使用原有文件模式，需手动选择 Git。Git 数据放在 `{remotePath}/_istart-git/v1/`，原有笔记备份和同步元数据继续保留。

首次 Git 同步从当前本地笔记开始。如果需要原有云端备份中的文件，先用文件模式恢复，再切换到 Git。所有参与 Git 同步的设备都应更新插件并选择 Git 模式。不要同时用两种模式写入同一批笔记。

首次接入的两个设备共享固定的空提交作为祖先。不同文件会合并；同名、不同内容的文件会要求选择版本，不会根据时间直接覆盖。

## 版本与合并

- 每次同步先保存本地提交，包括新增、修改和删除。
- 已发布的版本包以提交 SHA 命名，各设备并发发布不会覆盖同一个共享分支指针。
- 首次发布完整版本包，后续发布排除已上传版本的增量包。增量包依赖早期版本，请保留云端历史包。
- Markdown 等文本通过共同祖先做三方合并。重叠修改、删除与修改、附件修改冲突需要用户处理。
- 冲突不会覆盖本地文件。单文件恢复前会记录当前内容，恢复后的内容也会生成新提交。
- 删除会同步到其他设备，并通过 Obsidian 回收站处理本地删除。历史中仍保存之前的内容。
- 云端列表或下载失败会中止同步。文件在同步期间发生变化时，先保留新内容，下一次同步再合并。
- 应用合并结果前记录本地恢复日志。同步中断后再次手动同步，会合并尚未完成的结果和当前笔记。

## 范围与存储

Git 模式同步整个 Vault 中符合规则的普通文件，使用设置中的忽略规则与大小限制。隐藏路径、Obsidian 配置目录、插件凭证和 Git 元数据不纳入 Git 笔记同步。配置推送和原有插件备份仍为单独操作。

本地 Git 历史保存在 `{vault.configDir}/plugins/istart-note-ai/git-sync/`。因此恢复可在离线状态下完成。版本包与本地历史包含之前的笔记内容，删除当前文件不会自动清除历史。当前版本不自动清理历史包，也不提供额外加密。

文本自动合并限制为单份内容不超过 100 万字符，以控制手机内存开销；更大的文本通过版本选择处理。文件名需能跨设备表示，大小写、Unicode 形式、文件与目录冲突会中止操作。大型 Vault、附件和长期历史会增加首次下载、压缩、内存与存储开销。

此实现不提供标准 Git 网络服务器、Git LFS、子模块或复杂多共同祖先合并。Git bundle 可用标准 Git 校验和读取，但云端目录不是可直接 push 的 Git remote。

## 验证

`npm test` 覆盖独立设备首次接入、离线文本合并、冲突处理、附件、删除、并发发布、增量依赖、包损坏、标准 Git 兼容性、Obsidian 文件适配器、中断恢复和默认关闭自动操作。浏览器构建测试在不提供 Node 的 `require`、`process`、`Buffer` 全局对象的环境中运行 Git 内核。

Android/iOS 真机、实际百度网盘授权和网络服务仍需在安装插件后验证。
