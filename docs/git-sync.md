# 百度网盘 Git 同步

Git 模式用 JavaScript Git 内核保存真实提交，通过百度网盘上传、下载标准 Git bundle 文件。桌面、Android 和 iOS 使用相同协议，不需要系统 Git、终端或额外服务器。

## 使用

1. 在设置中启用百度网盘同步，填写百度应用信息并完成授权。
2. 选择「Git 版本同步」，在所有设备填写相同的远端路径。
   状态页顶部会显示当前模式、整库范围和本地文件数量；切换后立即刷新为「手动同步整库」「整库版本历史」和最近提交列表，不需要重启插件。
3. 点击「打开同步 → 同步整个笔记库」，或侧边栏「手动同步整库」。每个版本包包含整个同步范围的提交；上传一个版本包不代表只上传一份文档。
4. 若有冲突，选择本地或云端版本；文本冲突也可编辑合并内容后继续。
5. 在「整库版本历史」选择提交，查看整个笔记库的文件清单，以及相较上一版本的新增、修改和删除。可筛选路径、选择任意文件查看或恢复其内容；默认不选择当前打开的文档。
6. 点击「预览整库恢复」查看相对当前笔记库的具体增删改，再确认恢复。当前内容会先保存到历史；所选版本后新增的文件会移至回收站，已删除的历史文件会重新恢复。恢复生成新提交，保留后续历史，并在下次手动同步时传播。预览后如果文件发生变化，需要重新预览。

自动 Git 同步和启动时拉取配置默认关闭。这些开关属于本设备偏好，不会被云端配置开启。可选自动 Git 同步在前台每分钟运行，开启后也在启动时运行；应用被暂停或关闭时不保证继续同步。默认只在用户点击同步或恢复相关操作时创建提交，版本包仅在同步时交换。

## 从原有文件同步迁移

已有配置继续使用原有文件模式，需手动选择 Git。Git 数据放在 `{remotePath}/_istart-git/v1/`，原有笔记备份和同步元数据继续保留。

首次 Git 同步从当前本地笔记开始。如果需要原有云端备份中的文件，先用文件模式恢复，再切换到 Git。所有参与 Git 同步的设备都应更新插件并选择 Git 模式。不要同时用两种模式写入同一批笔记。

首次接入的两个设备共享固定的空提交作为祖先。不同文件会合并；同名、不同内容的文件会要求选择版本，不会根据时间直接覆盖。

## 版本与合并

- 每次同步先保存本地提交，包括新增、修改和删除。
- 已发布的版本包以提交 SHA 命名，各设备并发发布不会覆盖同一个共享分支指针。
- 首次发布完整版本包，后续发布排除已上传版本的增量包。增量包依赖早期版本，请保留云端历史包。
- Markdown 等文本通过共同祖先做三方合并。重叠修改、删除与修改、附件修改冲突需要用户处理。
- 冲突不会覆盖本地文件。单文件与整库恢复前会记录当前内容，恢复后的内容也会生成新提交。整库恢复提供具体文件变更预览，并保留后续提交。
- 删除会同步到其他设备，并通过 Obsidian 回收站处理本地删除。历史中仍保存之前的内容。
- 云端列表或下载失败会中止同步。文件在同步期间发生变化时，先保留新内容，下一次同步再合并。
- 应用合并结果前记录本地恢复日志。同步中断后再次手动同步，会合并尚未完成的结果和当前笔记。

## 范围与存储

这里的项目指当前打开的整个 Obsidian 笔记库（Vault）。Git 模式同步其中符合规则的普通文件，包括所有子目录的笔记和附件，使用设置中的忽略规则与大小限制。隐藏路径、Obsidian 配置目录、插件凭证和 Git 元数据不纳入 Git 笔记同步。配置推送和原有插件备份仍为单独操作。

本地 Git 历史保存在 `{vault.configDir}/plugins/istart-note-ai/git-sync/`。因此恢复可在离线状态下完成。版本包与本地历史包含之前的笔记内容，删除当前文件不会自动清除历史。当前版本不自动清理历史包，也不提供额外加密。

Git 版本保留原始文件名，不会因已有文件名包含 `*`、`?` 等 Windows 限制字符而拒绝保存。例如 `Knowledge/Concepts/_未分类/**体系结构模型**.md` 可按原名保存、同步与恢复。Windows 设备会在应用笔记修改前检查自身不支持的文件名，提示在原设备重命名后再同步，不会自动改名或跳过该文件。

文本自动合并限制为单份内容不超过 100 万字符，以控制手机内存开销；更大的文本通过版本选择处理。绝对路径、目录穿越、隐藏路径，以及大小写、Unicode 形式、文件与目录冲突仍会被拦截。大型 Vault、附件和长期历史会增加首次下载、压缩、内存与存储开销。

此实现不提供标准 Git 网络服务器、Git LFS、子模块或复杂多共同祖先合并。Git bundle 可用标准 Git 校验和读取，但云端目录不是可直接 push 的 Git remote。

## 验证

`npm test` 覆盖独立设备首次接入、离线文本合并、冲突处理、附件、删除、并发发布、增量依赖、包损坏、标准 Git 兼容性、Obsidian 文件适配器、中断恢复、特殊字符文件名往返与恢复、Windows 写入前检查，以及默认关闭自动操作。整库测试覆盖不依赖当前文档的跨目录同步、全库版本清单、整库恢复后的历史保留与跨设备传播、排除规则保护、预览后的编辑保护和恢复中断处理。浏览器构建测试在不提供 Node 的 `require`、`process`、`Buffer` 全局对象的环境中运行 Git 内核。

Android/iOS 真机、实际百度网盘授权和网络服务仍需在安装插件后验证。
