# 多会话 Agent 助手

从左侧「IStart 工作台」图标或「AI 助手」命令打开侧栏。顶部在助手、批注和数据同步之间切换；问答、Agent、小说演绎是助手内的模式。「知识库问答」打开问答模式。原功能面板和两个 AI 快捷弹窗命令保留 ID，统一打开助手。

## 任务快捷入口

助手输入区提供折叠的常用任务入口。已有命令、编辑器右键、悬浮工具栏和写作状态栏使用同一任务执行机制。

- **直接执行**：续写、插写、润色、扩写、解释、总结、下一章、角色提取、AI 批注与概念补全，先捕获笔记和原文位置；解释与总结为只读问答。
- **参数卡**：知识提问、阅读项目、新建作品、实用模板、续写与插写设置，在输入区填写参数并开始任务；参数随会话保存。
- **知识债务**：只读列出空概念、孤立问题、未完成阅读和长期草稿；切换 Agent 后指定页面或每批最多5页生成概念补全预览。
- **文档美化**：调用现有格式化流程，生成全文修改预览，原文改变时阻止覆盖。
- **错别字甄别**：只读检查固定选区或全文，结果存入会话；点击「查看校对定位」打开定位列表。原文变化后旧定位禁用。
- **已有批注**：编辑弹窗的 AI 重写与卡片的 AI 建议进入 Agent；建议生成追加预览，重写生成替换预览，复用本地编辑规则保护高亮、脚注及其他共享引用。
- **原稿导入**：保留选择、切章、分类调整、清洗和确认导入向导；AI 分类与元数据分析通过 Agent 执行，结果与错误记录在会话中。关闭向导或取消导入会停止 AI 请求，不会在请求完成后继续写入。分析失败会提示并保留规则导入，可在会话中重试分析。

明确点击的任务直接调用对应工具，不额外让模型规划。结果可在会话中继续讨论，修改草稿可继续缩短或改写，预览后应用。重新生成沿用原任务参数与位置，失效锚点不会改向其他笔记；中断任务可从保存的工具断点继续。

新任务保留已有对话与输入草稿。独立「全部功能」面板已移除；同步、普通批注编辑、校对定位和原稿准备仍使用专用界面，AI 生成共用 Agent。

## 复制与插入位置

- 消息正文、引用、执行结果与修改预览可选中复制；流式更新会保留正在选择的文字。
- 用户消息可复制正文或连同引用复制；助手消息可复制回答或完整消息。执行步骤、文件原文、修改后全文与新增内容各有复制按钮。
- 会话菜单的「复制整个会话」包含摘要、双方消息、来源、执行记录和修改预览。
- 编辑器在拥有焦点时记录原文与位置快照；进入 Agent 后优先使用会话的固定目标，不依赖编辑器保持焦点。
- 通过 @ 只引用了笔记而没有光标，或需要改变目标时，点击输入区「设置插入位置」，在只读原文中点击位置并确认。引用栏显示行列。
- 生成好的回答可用「保存或写入回答 → 插入到已设置位置」生成预览，无需重新生成回答。「插入本轮原光标位置」仍沿用该轮原始位置。
- 应用修改后，会话光标推进到修改末尾，便于继续写作。手动修改原文会使旧快照失效，需要重新设置；不会猜测新位置或覆盖新内容。

## 会话与上下文

- 顶部 `+` 创建独立会话，标题按钮打开可搜索的历史列表。各会话保存独立的草稿、引用、消息、模式和修改记录。
- 会话菜单支持重命名、置顶、归档、恢复、删除、分支和导出。消息上的分支按钮从该消息继续；继承的待应用修改只作历史参考，不重复执行。
- 输入 `@` 或点击引用按钮选择笔记；选区按钮捕获最近打开的 Markdown 笔记、选区和光标。在编辑器中打开 AI 助手也会先捕获这些位置。
- 切换文件和会话不会重定向引用或写入目标。每轮发送读取一次引用快照；选区原文已变化时，需重新选中并引用。旧光标失效时不会自动选择新位置。
- 批注卡片菜单的「在 Agent 中继续讨论」会带入原文和现有批注。
- Ctrl/Cmd+Enter 发送；输入法组合期间不触发。手机侧栏根据可见视口和 Obsidian 键盘高度收缩，输入区保留在底部。

## 问答与 Agent

问答模式可读取、检索、总结与解释，不能生成文件修改草稿。Agent 模式通过真实的工具执行循环组合能力，工具结果返回模型后再决定下一步。工具名称和参数在本地校验，工具步数默认 8、可调 2–20，每轮最多运行 5 分钟。单会话串行，最多同时生成两个会话；文件修改统一串行应用。

| 能力 | 工具 |
| --- | --- |
| 知识库检索、分页读取笔记与未保存草稿 | `knowledge.search`、`note.read` |
| 总结、解释、扩写、润色、章节补全 | `document.generate` |
| 插入、替换选区、追加或新建笔记 | `note.propose`、`note.create` |
| 图表、公式 | `diagram.generate` |
| 问题分类、结构化问答与概念/问题索引 | `question.classify`、`question.generate` |
| 概念扫描、单页及分批补全 | `concept.scan`、`concept.complete`、`concept.complete_batch` |
| 续写、插写、润色、下一章、角色提取 | `writing.generate` |
| 完整作品规划与项目文件 | `writing.plan` |
| AI 批注草稿、已有批注建议 | `annotation.assist` |
| 阅读地图和章节骨架、读前问题与项目续接 | `reading.plan`、`reading.questions`、`reading.resume` |
| 章节总结、费曼检验 | `reading.review` |
| 检查表、SOP、行动计划等模板 | `artifact.generate` |

阅读项目包含作者、前置知识、章节关系图、概念占位页和章节骨架。`reading.resume` 接着补齐缺失的读前问题，默认每次一章，最多可指定五章；会保留手写问题和正文，并更新地图中的已生成数量和完成状态。可以在尚未保存的项目草稿上连续处理，也兼容原有阅读项目补全逻辑。超过本轮步数时可继续提问处理剩余章节，已完成的章节会跳过。

知识问答同时预览 Q&A、概念占位页、问题索引和 Mermaid 问题演化图。实用模板可同时生成今日记录，支持一次性、模板或例行使用方式，以及严格来源、平衡和自由生成策略。概念批量补全每批最多 5 页，应用后继续下一批。

知识检索沿用现有标题、标签、章节和链接索引；非写作上下文默认排除作品私有资料。长笔记用 `note.read` 的 `offset` 和 `length` 分页，单页最多 18,000 字符且受本轮资料预算约束。返回的下一段位置以实际提供的片段为准，不会跳过被截断的正文。

## 小说演绎与进化模式

在侧栏选择「小说演绎与进化模式」，将小说项目章节作为第一篇引用。项目需要 `_作品.md` 与 `_角色/`。在「参演设置」选择1–4名角色和每次连续推进次数，默认最多推进6次后暂停，可再次继续。开场方式可按场景自然决定、先展开场景，或指定参演角色先回应。

### 实时呈现与自然接话

- 角色对白显示角色姓名和气泡；动作、环境、转场、心理描写显示为无气泡、无署名的正文。角色的一次回应可以包含交错的多个对白与叙述块。
- 支持的模型服务通过 SSE 边生成边显示。服务不支持流式或浏览器跨域请求失败时，显示「等待完整回应」，收到完整结果再呈现，不模拟逐字打字。
- 调度根据已发生的公开内容选择下一位角色、推进场景或收场。允许同一角色连续回应；不会强制所有角色轮流说话。场景演绎不能代写角色对白或私有心理。
- 已显示的内容按顺序保存，后续只追加，不再回填前文、重排或概括台词。角色完成当前回应后交出话轮，不按固定字数压缩谈话。
- 「对话现场」与「小说正文」读取相同的内容块，只改变排版。复制、保存和导出保留原文。

### 暂停、介入与继续

| 操作 | 行为 |
| --- | --- |
| 自动接话 | 连续推进，达到次数或预算边界后暂停 |
| 推进一步 | 完成一个角色回应或场景事件后暂停 |
| 说完后暂停 | 当前回应完成后停止调度 |
| 立即打断 | 取消当前请求，保留已显示文字，未完成片段单独标记 |
| 指定下一步 | 选择参演角色或「推进情境」，在下一个回应边界生效 |
| 输入框发送导演指令 | 指令进入本场调度记录，不作为角色已经说出的台词；正在生成时排队生效 |
| 结束本场 | 当前回应结束后进入待确认状态 |
| 保留草稿并另起一场 | 保留本场原稿，不将它纳入正式剧情，允许发起新场景 |

暂停和中断后沿用同一场景、角色卡快照和来源继续，不增加重复用户消息或重放已完成的回应。对于未完成片段，作者需要明确选择「保留此片段」或「跳过此片段」，原稿始终留存。新的请求续接已保留的内容，不承诺恢复服务端已经取消的同一条流。

每次连续执行最多5分钟，暂停时间不计入下一次执行。角色卡或引用原文改变时拒绝直接续演，保留已有内容，并要求另起一场使用新资料。场景未确认期间固定角色和引用；确认或另起一场后才能调整。

### 信息边界、确认与角色进化

- 每个角色只接收自己的角色卡、公开演绎和属于自己的私有心理描写。其他角色与调度不接收这些私有内容。原文引用与世界设定作为作者参考背景提供，模型是否严格遵守人物知识边界仍需作者审核。
- 当场停下后，可按块修订正文或取消将某块纳入剧情；对白身份与私有心理的可见范围固定。确认保存独立的正文版本，原始演绎不被覆盖。后续角色记忆使用已确认版本，并继续按可见范围筛选。
- 确认剧情后才逐角色推演变化，每次推演同样只接收本角色可知的剧情与自己的角色卡，避免将他人私有心理写入其记忆。每条更新必须引用本角色可知的已确认正文中存在的原句，生成角色卡增量修改预览；应用后写入角色卡，保留原设定。无充分依据时不更新。
- 推演失败可单独重试；也可明确选择「保留剧情，暂不更新角色」。存在待处理角色卡修改时，先应用或放弃，再发起下一场。
- 确认只保存会话中的正式剧情。通过「保存或写入回答」另存笔记或追加到章节时，仍先生成修改预览。

### 保存与兼容

会话存储升级为 v2，兼容读取 v1，并在首次升级前保留 `sessions.v1.backup.json`。新版会话应由新版插件读写，避免旧版插件按旧结构修改新场景。新版场景使用带版本的内容块，记录类型、顺序、角色归属、可见性和完成状态。流式期间定期保存，每次回应完成后立即保存。重启时未完成的块恢复为中断状态，可处理后继续。长对话达到上下文或保存上限时暂停，已有台词不会自动总结或裁掉；可确认分场、提高预算，或将剧情整理进章节后开始新场景。

旧版 `turns` 场景仍按原文展示，不自动猜测或拆分对白。旧版合成正文、通用会话摘要和未确认的草稿不自动作为新版角色的公开经历；继续创作时，可引用作者已整理的章节开始新场景。

遇到模型返回格式错误时，会暂停并保留已显示的内容；可以处理片段、指定角色后继续同一场景。展开「执行与资料记录」可检查角色调度、作者指令和失败请求的原始返回。协议内容和内部 Agent 分工不进入正常的小说阅读界面。

## 预览与应用

所有生成工具只产生内容或修改草稿。展开「查看修改」检查目标路径和新增/删除内容，点击「应用修改」才会写入。问答结果也能通过消息操作生成“保存新笔记”“追加到本轮引用笔记”“插入原光标”的预览。

未应用的草稿可继续读取和调整。多步任务或后续追问修改同一文件时，会将相关变更合并为一份最新草稿，并保留最初原文作为写入校验基准；旧版本标为「已由后续草稿替代」，不能再次应用。涉及共享索引的多份修改会一起合并，避免阅读进度或问题索引互相覆盖。草稿内容会明确标为未保存，不作为已经写入 Vault 的来源证据。

写入前先检查整份修改涉及的全部文件，再在每次实际写入时核对原文。编辑器中的修改保留原生撤销；没有打开编辑器的文件使用 Vault 的原子文本处理。新文件同名占用和原文变化都会阻止覆盖。

多文件修改不是文件系统事务：磁盘错误可能造成部分文件已经写入。再次应用时，会跳过内容已与预览一致的文件，继续其余部分；已经发生其他编辑的文件仍会阻止覆盖。已应用修改不会重复插入。

停止按钮会立即结束本轮处理，忽略迟到响应，且不执行后续工具。非流式 Obsidian 请求无法撤销已送达服务端的生成。

## 任务继续与重新生成

最后一条中断、取消或出错的任务有断点时，显示「继续任务」。断点在模型请求和工具执行前后保存，包含原引用快照、项目范围、工具结果与尚未完成的工具请求。

- **继续任务**：沿用原消息和已完成的工具结果，不新增重复用户消息或草稿。未完成的那一个工具可以重新执行，已完成步骤会跳过；仍需点击应用才会写入。
- **重新生成**：按当前会话引用与设置重新开始处理用户请求。旧草稿不会自动应用，若新草稿调整同一文件，会替代相应旧版本。
- **从此处分支**：复制对话作为另一段会话的历史参考，不继承可执行断点。

继续前会核对来源是否仍与断点一致。原文变化时保留旧草稿并要求基于新内容重新生成；执行模式或检索范围改变时，需切回原设置才能继续，或者使用当前设置重新生成。继续操作也受每轮步数和时间上限约束。

## 存储、技能与模型

- 本地记录：`<vault.configDir>/plugins/istart-note-ai/agent/sessions.json`，有版本校验，与 `data.json` 分离，串行保存。损坏或未知版本的历史不会被空数据覆盖。
- 重启时，运行中的消息转为中断状态，有断点的任务可以继续；写入中的修改恢复为可检查的待应用状态。断点会验证版本、消息角色、来源和工具记录，损坏数据不会作为新请求执行。
- 长对话保留原消息，同时生成可查看的摘要。每轮引用、最近历史和工具结果受资料字符预算约束；修改的实际应用状态优先于旧摘要。
- 技能在每轮开始时按固定引用所属项目选择，之后切换活动文件不会改变本轮技能。
- 沿用现有模型设置。执行协议使用可校验的 JSON 工具请求，因此不依赖服务商原生 function calling。只有最终回答内容显示给用户，工具参数与隐藏思考不作为回答流展示。
- 可在「辅助 → Agent 对话」启用 SSE 流式输出。浏览器跨域请求失败时回退到完整响应；收到数据后的连接失败不会自动重复请求。
- 「共享会话历史」默认关闭。主动启用后生成 `IStart/Agent Sessions/history.json`；该文件可由 Git 模式或其他 Vault 同步服务同步，旧文件同步模式沿用其原有范围。共享时按消息 ID 合并，保留删除记录，避免旧设备恢复已删除会话。会话文件不包含模型/百度凭证，但包含对话和引用原文。关闭共享不会删除已有共享文件。

## 代码边界与验证

`src/core/agent/` 定义会话模型、独立存储、执行循环、工具注册、引用快照与修改应用。`src/features/agent/` 负责会话控制和 Obsidian ItemView。AI 生成器复用现有实现，并接受每轮固定的 LLM 客户端；界面不直接操作模型或文件。

运行 `npm run ci` 完成单元/集成回归、类型检查和生产构建。重点覆盖断点续接、未完成工具恢复、草稿跨轮调整、完整阅读项目生成、来源和模式变化保护、取消与迟到响应、工具回传、问答模式约束、修改冲突、重复/部分应用恢复、技能隔离、SSE 解码和共享历史。浏览器模拟检查覆盖继续任务按钮、会话重开、模型设置刷新、窄屏和键盘布局。真实模型质量、服务商跨域支持和 Obsidian 设备行为仍需使用用户配置进行实机验证。
